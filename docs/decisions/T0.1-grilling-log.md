# T0.1 grilling log

Running record of decisions made in the T0.1 grill session. Each row is settled;
ADRs and `GLOSSARY.md` carry the durable versions.

| # | Question | Decision | Lands in |
|---|----------|----------|----------|
| Q1 | Team, timeline, infra budget | **Team:** one human (decides, gates, merges) + up to 3 supervised agent builders. **Timeline:** Phase 0 in ~1 day, then rapid iteration (no fixed 12-week plan). **Budget:** hard ceiling of $5/mo Workers Paid + $20/mo usage = **$25/mo total infra** pre-launch; any paid service beyond that needs explicit approval. | `01_GOAL` open decisions; constrains every paid choice below |
| Q2 | Data residency | **No residency guarantee for MVP.** One default location for D1/R2. Every tenant carries a `region` field (only value `default` for now) so EU-jurisdiction storage can be added later without a schema change. No GDPR data-residency claims in marketing until it exists. | ADR-0004 (tenant isolation); data model |
| Q3 | Tenant isolation | **Shared D1 + `tenant_id`, enforced by `packages/storage` requiring branded `TenantId`.** Global users with per-tenant memberships; one Active tenant per request; R2 keys `t/{tenantId}/d/{documentId}/v{n}` built only in storage; sharding deferred to ADR-0007. | [ADR-0004](../adr/0004-tenant-isolation.md), `GLOSSARY.md` |
| Q4 | Auth provider | **Better-Auth on D1**, wrapped by `packages/auth`. Magic link / OTP + Google OAuth, no passwords at launch. Cookie sessions in D1. Organizations = Tenants. Signers are not Users. | [ADR-0003](../adr/0003-auth-provider.md) |
| Q5 | Email provider | **Cloudflare Email Service** (Workers `send_email` binding), since secondary sources report 3,000 sends/month included in Workers Paid and ~$0.35 per 1,000 after. **Fallback: Resend free tier** (3,000/mo). Both sit behind one `EmailSender` interface; dev and tests use a captured outbox, so CI never sends real mail. ASSUMPTION: the included allowance and the overage rate come from third-party summaries, because developers.cloudflare.com was unreachable from the build environment. The service is in public beta. Confirming both against the Cloudflare dashboard is an acceptance criterion of the email ticket. | Email adapter ticket (Phase 1); `02_TOOLS` |
| Q6 | Frontend framework | **React + Vite SPA** on Workers static assets; React Router v7 data mode, TanStack Query, Tailwind + shadcn/ui, PDF.js. Web calls API over HTTP only; shared Zod schemas in `packages/domain`. | [ADR-0002](../adr/0002-frontend-framework.md) |
| Q7 | Monorepo & tooling | **pnpm + Turborepo (local cache), Node 22, exact pins, TS strict+, ESLint flat + typescript-eslint strict + eslint-plugin-boundaries + custom no-D1/R2-outside-storage rule, Prettier, Vitest + vitest-pool-workers, Playwright.** Biome rejected (can't express boundary rules). | [ADR-0001](../adr/0001-monorepo-and-tooling.md) |
| Q8 | Pricing tiers & limits | **Free:** 1 member, 500 MB, 25 MB/file, 50 page ops/mo, 3 envelopes/mo, share links ≤7 days without password. **Pro ($12/mo or $120/yr):** ≤5 members, 20 GB, 100 MB/file, unlimited ops (fair use 2,000/mo), 50 envelopes/mo, full share-link controls. Team plan is out of the MVP. Limits are enforced server-side from `usage`; Stripe arrives in Phase 4 behind a human gate. | `01_GOAL`; `usage` table; Phase 4 billing spec |
| Q9 | Preview environments | **Per-PR isolated resources** `inkly-pr-<n>` (Worker + D1 + R2 + KV), created/migrated by a GitHub Action on PR open/sync, deleted on PR close, plus a nightly sweeper. Environments: `preview-pr-<n>` and `production`; no shared staging. Human step: Cloudflare API token (Workers, D1, R2, KV edit) and account ID stored as GitHub secrets `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`, done via a guided script. | T0.8 (`cf-deploy-preview`) |
| Q10 | Issue tracker & labels | **GitHub Issues in this repo.** Labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`, `risk:high`, `needs-human`, `factory-pause`, `phase:0`–`phase:4`. T0.2–T0.10 are filed as issues after gate approval. The T0.10 metrics issue doubles as the tracking issue that carries the kill switch. Branches follow `t/<issue#>-<slug>`. | `docs/agents/` (skill-pack setup, T0.4); T0.10 |
