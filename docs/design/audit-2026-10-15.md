# Design audit, 2026-10-15

Run with the design plugin's `design-system`, `accessibility-review`, `design-critique`,
`ux-copy` and `design-handoff` skills against PR #25. The plugin's Figma connector could not
connect from the cloud session, so the audit read the code and the verify-app screenshots
instead.

## Design system

**Components reviewed:** 6 (Button, Badge, Sheet, Field, EmptyState, AppShell) · **Score:** 74 → 92/100

| Finding | Fix |
|---------|-----|
| Shadows written inline, one with a raw `rgb()` color | `shadow-stamp`, `shadow-stamp-lift`, `shadow-stamp-ink`, `shadow-sheet` and `shadow-margin` theme tokens; `--shadow-color` per theme |
| Motion values inline (`duration-150 ease-out`) | `--duration-fast` and `--ease-ink` set as Tailwind's default transition |
| Fold size hardcoded twice | `--fold` token |
| `Badge` used `tone` while `Button` used `variant` | renamed to `variant` |
| Button had no loading state | `loading` prop with `aria-busy` |
| EmptyState had no slot for its action | `action` prop |
| Components undocumented beyond the reference page | `docs/design/components.md` |
| Nothing stopped a raw color creeping back in | `inkly/no-raw-colors` lint rule in `apps/web/src`, with a lint fixture proving it fires. It caught the `rgb()` above. |

## Accessibility (WCAG 2.1 AA, plus 2.2 AA where axe can test it)

| # | Issue | Criterion | Severity | Fix |
|---|-------|-----------|----------|-----|
| 1 | Design-system link was about 21px tall | 2.5.8 Target size | Minor | padded to ≥ 24px; axe `wcag22aa` now runs on every checkpoint |
| 2 | Primary nav could overflow at 320px | 1.4.10 Reflow | Major | nav wraps; J-001 fails if anything scrolls horizontally at 320px (proven against a forced 96px overflow) |
| 3 | Required-field `*` had no explanation | 3.3.2 Labels or instructions | Minor | "Fields marked * are required" above the form |
| 4 | Error message said the fix but not the problem | 3.3.1 Error identification | Minor | "This password is too short. Use at least 8 characters." |
| 5 | Filled buttons lose their edge in Windows forced-colors mode | 1.4.11 Non-text contrast | Minor | transparent border on every button |

Already passing: contrast for all 27 token pairs in both themes (unit test), skip link and
focus outline (J-001), focus moved to the `h1` after navigation, `aria-current` on nav, labelled
fields with `aria-describedby`, status conveyed by text, reduced motion. Not automatable here:
a screen-reader pass with VoiceOver or NVDA, recommended before beta.

## Critique

Works well: the document-desk metaphor is consistent from wordmark to empty states, the single
red accent keeps hierarchy obvious, and dark mode keeps the same character instead of inverting.

| Finding | Severity | Decision |
|---------|----------|----------|
| Empty states have no call to action | Moderate | kept: upload, envelopes and links don't exist yet, and a dead button is worse. `action` slot is ready for when they do. |
| "Design system" link sits in the product sidebar | Minor | kept while the app is pre-beta; move behind a dev flag before launch |
| Wide empty right column on large screens | Minor | kept: it fills once document lists exist |

## UX copy

| Before | After | Why |
|--------|-------|-----|
| Nothing on the desk yet / No envelopes in flight / Nothing shared yet | No documents yet / No envelopes yet / No share links yet | clear, consistent with glossary nouns, translates without idioms |

| Back to documents | Go to documents | the user may not have come from there |
